# Add Tab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add becomes a third tab (Library tree | PDF reader | Add editor) beside Decks and Browse; the Add dock, the PDF dock and the editor-toolbar "Library…" button are deleted; one reader serves the Add tab and Browse's viewer mode.

**Architecture:** Two new modules carry the new behaviour: `reader_host.py` owns the one `PdfSidebar` and moves it between its home (the Add page's reader slot) and Browse's viewer mode; `library_tree.py` is Klaus's own Library view over the index `library_sidebar` already builds. `single_window.py` grows a third page and loses the Add dock; `library_viewer.py` lends and gives back the reader instead of resizing a dock; `__init__.py`, `pdf_handler.py`, `status_bar.py` and `bottom_row.py` lose the dock, its placement state and its toggles.

**Tech Stack:** Python 3, PyQt6 through `aqt.qt`, Anki `gui_hooks`, the repo's offscreen harness (`tests/*.py` with `anki_stubs`).

**Spec:** `docs/superpowers/specs/2026-10-01-add-tab-design.md`

## Global Constraints

- Starts only after the PDF-reader session pings that phase 5 is committed (spec, Rulings); `PdfSidebar` is imported from `klausmate.reader_panel`, `ReaderTabs` from `klausmate.reader_tabs`.
- ONE `PdfSidebar` instance for its whole life, `host_key="editor"`, its `_sync_key` kept; re-parenting never rebuilds it (spec, Rulings). The only rebuilds: a dead C++ object, and the fallback transition in Task 1.
- The reader is never re-parented across top-level windows (spec, "The reader"); both homes are under `mw`.
- No `exec()` on any dialog or menu (K-114); js-message handlers that open a window defer with `QTimer.singleShot(0, …)`.
- Every hook body is `try/except Exception` with a `[klausmate]` print; nothing raises into Anki.
- Edit Current keeps its dock untouched: `_dock(mw, "edit", …)`, `_new_edit_dock`, `_reap_edit`, `show_dock("edit")`, `hide_dock`, `save/restore_dock_state` stay.
- Tests run as `env QT_QPA_PLATFORM=offscreen PYTHONDONTWRITEBYTECODE=1 python3 tests/<file>.py` from the add-on root, with `check/section/report` from `anki_stubs`; the suite loop is `for t in tests/test_*.py; do env QT_QPA_PLATFORM=offscreen PYTHONDONTWRITEBYTECODE=1 perl -e 'alarm 120; exec @ARGV' python3 "$t" >/dev/null || echo "FAIL $t"; done`.
- `user_files/` and `meta.json*` are never staged. Commit only when the user asks; stage by name, by hunk where a file carries foreign hunks (`__init__.py` holds K-320's 30 uncommitted lines at ~1333; the single-window hunks in `__init__.py`, `bottom_row.py`, `status_bar.py`, `addons_menu.py`, `browse_toggles.py`, `config.*`, the docs and tests are this session's and ride along).
- Always edit the main checkout (Anki loads it through a symlink); never drive the running Anki.

## Rulings made while planning

- `reader_host.editor()` (spec, "Insert target") is not built: nothing reads the reader's editor — the only readers of `sidebar._editor` were `PdfDock`'s `_ensure_sidebar_pdf`, and the reader's inserts are a `QDrag` and the clipboard. `PdfSidebar` is constructed with `editor=None`. The spec bullet is updated to say so.
- The reader's tab strip needs no move: `PdfSidebar` inserts `ReaderTabs` into its own layout and 2222af8's `_PanelBar` takes it out; deleting `_PanelBar` (Task 3) leaves the strip above the page, which is the spec's "Chrome" bullet.

## Review Focus

1. Sync (Anki's close-all) while the Add tab shows: Add is destroyed, the editor slot must show its placeholder, the reader must keep its tabs and stay a child of the reader slot, the tab must stay selected (Task 5 test "close-all on the Add tab").
2. Browse closed with ✕ while in viewer mode: the reader must be back home before Browse is deleted, no `RuntimeError`, the Add tab shows it again (Task 2 test "closing Browse in viewer mode gives the reader back first").
3. Double-click a PDF in Browse while the Add tab already shows that document: the one reader moves into Browse, the Add slot is empty, `b` then `a` shows it back after `leave` only (Task 2 test "lend while the home is showing").
4. A `pdf_tabs.json` from an older build with `placement`/`geom`: read ignores both, the next save drops them, no exception (Task 3 test "legacy placement keys are dropped on read and on save").
5. The single window is disabled mid-session after the reader exists under the Add page, then a stock Browse enters viewer mode: the reader must not cross top-level windows; a fresh one is built under Browse and the old one released (Task 1 test "lend into another top-level window rebuilds, never moves").

### Task 1: `reader_host.py` — the one reader and its two homes

**Files:**
- Create: `klausmate/reader_host.py`
- Test: `tests/test_reader_host.py`

**Interfaces:**
- Consumes: `klausmate.reader_panel.PdfSidebar(editor, parent=None, host_key="editor")` (phase 5), `PdfSidebar.cleanup()`.
- Produces (module functions, all guarded, all `[klausmate] reader host: …` on failure):
  - `make_reader: Callable[[QWidget], QWidget] | None = None` — test seam; `None` means `reader_panel.PdfSidebar(None, parent=parent, host_key="editor")`.
  - `set_home(slot) -> None` — the Add page's reader slot (a `QWidget` with a zero-margin `QVBoxLayout`); `None` clears it.
  - `has_home() -> bool` — a live home slot exists (`RuntimeError` on a dead one counts as none).
  - `reader(parent=None)` — the one instance, built on first call under `parent` or the home; `None` when there is nowhere to put it; a dead C++ object (`sip.isdeleted` or `RuntimeError`) is forgotten and rebuilt.
  - `lend(container) -> None` — re-parents the reader into `container`'s layout (`addWidget`) and shows it; builds it there when none exists; if the reader exists and `container.window() is not reader.window()`, calls `release()` first and builds a fresh one under `container` (fallback transition, Review Focus 5).
  - `give_back() -> None` — re-parents the reader into the home slot; with no live home it stays where it is.
  - `borrowed() -> bool` — the reader exists and its parent is not the home slot.
  - `release() -> None` — `cleanup()` the reader if alive, forget it.
