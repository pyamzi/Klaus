# Automatic Sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Klaus syncs with AnkiWeb in the background (idle, after review),
hides Anki's Sync button (it reads **Log In** while logged out), and shows a
sync status entry that syncs on click.

**Architecture:** One new module, `klausmate/auto_sync.py`. It is aqt-free
above its "aqt glue" divider (policy, copy, toolbar HTML rewrite and
stand-down check). Below the divider is the glue: tick, activity filter,
the quiet backend sync, hooks and listeners. `bottom_row` and
`status_bar.StatusBar` render its `entry_state()`. Preferences gets one key
and one switch.

**Tech Stack:** Python 3.9-compatible source (`from __future__ import
annotations`), PyQt6 via `aqt.qt`, Anki 26.09.2 `gui_hooks`. Tests are
headless with `anki_stubs` and offscreen Qt.

**Spec:** `docs/superpowers/specs/2026-10-02-auto-sync-design.md`

## Global Constraints

- Constants: `IDLE_S = 120`, `MIN_GAP_S = 300`, `AFTER_REVIEW_S = 30`, `AFTER_REVIEW_QUIET_S = 5`, `FAIL_LIMIT = 3`, `TICK_MS = 10_000`.
- **Never sync automatically in `mw.state == "review"`.** Never start a full sync automatically. Never touch Anki's profile open/close sync.
- **Quiet syncs show no window, dialog or tooltip.** The only exception is AnkiWeb's `server_message`, shown through `showText` the way Anki shows it.
- **Copy, verbatim:**
  - `"Log In"`, link title `"Log in to AnkiWeb"`
  - `"Synced just now"`, `"Synced 4 min ago"`, `"Synced 2 h ago"`
  - `"Not synced yet"`
  - `"Sync failed — click to retry"`
  - `"Full sync needed — click to choose"`
  - Switch: `"Sync automatically"`, description `"Sync with AnkiWeb in the background and hide the Sync button. Press Y or click the sync status to sync now."`
  - Stand-down description: `"The Auto Sync add-on is installed and handles syncing."`
- **The Sync link is hidden, never removed.** Both `id="sync"` and `id=sync-spinner` stay in the DOM.
- Config key `auto_sync`, default `true`.
- **Project rules:**
  - no app-modal `exec()`;
  - clicks from a webview open a tick later (`QTimer.singleShot(0, …)`);
  - `try/except` around every Qt/aqt call, logging `print("[klausmate] …")`;
  - tests use temp dirs only;
  - edit the main checkout;
  - never stage `user_files/`, `meta.json*`, or the uncommitted K-320 `debug_progress` block and mode flip in `klausmate/__init__.py`. Stage that file's hunk as a blob built from HEAD plus this plan's hunk (`git hash-object -w` + `git update-index --cacheinfo`).
- **Test command for one file:** `env QT_QPA_PLATFORM=offscreen PYTHONDONTWRITEBYTECODE=1 python3 tests/<file>`. **Whole suite:** the loop in CLAUDE.md.

## Verified facts the tasks rely on

- `mw.toolbar.redraw()` does **not** rebuild links. Only `mw.toolbar.draw()`
  re-runs `top_toolbar_did_init_links`. After Anki's login-then-sync,
  `_refresh_after_sync` calls `redraw()`, so the **Log In** link stays
  until Klaus calls `draw()`. Klaus must call `draw()` itself when the
  login state changes (Task 2). This corrects the spec's Risks section,
  which assumed the link was rebuilt.
- **Last sync time:** `mw.col.db.scalar("select ls from col")`, in
  milliseconds; 0 means never.
- **The backend call:** `mw.col.sync_collection(auth, mw.pm.media_syncing_enabled())`
  → `SyncOutput`. The fields used are `.required` (compared to
  `out.NO_CHANGES`), `.host_number`, `.new_endpoint` and
  `.server_message`.
- **Errors:** `anki.errors.SyncError` has `.kind`, and
  `SyncErrorKind.AUTH` marks a bad login. `anki.errors.Interrupted`
  means the sync was cancelled.
- **Running it:** `mw.taskman.run_in_background(task, on_done)`, where
  `on_done(fut)` runs on the main thread; `uses_collection` defaults to
  True.
- **Anki's link** (25.09 source; 26.09 has the same names):
  `<a class=hitem tabindex="-1" aria-label="{name}" title="{title}" id="sync" href=# onclick="return pycmd('sync')"\n>{name}<img id=sync-spinner src='/_anki/imgs/refresh.svg'>\n</a>`

## Review Focus

1. **The toolbar after you log in through Log In.** The button must
   disappear once you're logged in. `redraw()` alone leaves "Log In",
   so a test is pinned in Task 2.
2. **Logging out in Anki's Preferences.** Within one tick the button
   must come back as Log In and the entry must hide. Pinned in Task 2.
3. **A full sync pending while you press `y` and cancel the
   upload/download choice.** Auto sync must not loop into the choice.
   A later quiet sync sees FULL again and re-marks it pending without
   asking. Pinned in Task 2.
4. **Your own sync, through `y` or Log In, while a quiet sync is
   running.** That can't happen: the quiet sync holds the collection
   and `due` is False while either kind is running. Anki's progress
   window would just queue. Pinned through `ready` in Task 1, and the
   running flag in Task 2.
5. **Translated Anki (a non-English "Sync" label).** `link_html` must
   find the link by `id="sync"`, never by its text. Pinned in Task 1.

  - **`setup()`** registers:

  - **`_Activity(QObject).eventFilter`** sets `_last_input = clock()` for
    `KeyPress`, `MouseButtonPress` and `Wheel`, and returns `False`.
  - **`_tick()`:**
    1. If the login state differs from `_drawn_logged_in`, call
       `mw.toolbar.draw()`.
    2. If `due(clock(), …, state=mw.state, ready=…)` is True, call
       `_run_quiet()`. `ready` is `active() and mw._can_sync_unattended()
       and not (_quiet_running or _anki_running or
       mw.media_syncer.is_syncing() or _full_pending)`.
    3. Notify the listeners.
  - **`_run_quiet()`:** set `_last_attempt = clock()`,
    `_review_left_at = None` and `_quiet_running = True`; fire
    `gui_hooks.sync_will_start()`; then call
    `mw.taskman.run_in_background(lambda: mw.col.sync_collection(auth,
    mw.pm.media_syncing_enabled()), _on_done)`.
  - **`_on_done(fut)`** follows the spec's step 3 exactly, in a
    `try`/`finally`. The `finally` sets `_quiet_running = False`, then
    calls `mw.col.models._clear_cache()`, `gui_hooks.sync_did_finish()`,
    `mw.reset()` and `mw.toolbar.update_sync_status()`, and notifies the
    listeners.
    - Import `SyncError`, `SyncErrorKind` and `Interrupted` from
      `anki.errors` inside the function.
    - An AUTH error calls `mw.pm.clear_sync_auth()` then
      `mw.toolbar.draw()`.
  - **`_on_anki_sync_start` / `_on_anki_sync_finish`:** both return at
    once while `_quiet_running`, because Klaus fired the hooks itself.
    - Start sets `_anki_running = True`.
    - Finish sets `_anki_running = False`, `_last_attempt = clock()`,
      `_failures = 0` and `_full_pending = False`. If the login state
      changed, it calls `mw.toolbar.draw()`, then notifies the
      listeners.
  - **`_on_links(links, toolbar)`:** record
    `_drawn_logged_in = bool(mw.pm.sync_auth())` and replace each item
    where `is_sync_link(item)` is True with
    `link_html(item, logged_in=_drawn_logged_in, active=active())`.
  - **`entry_state()`:** `entry_text(time.time(), ls/1000 or None,
    _failures, _full_pending)`, where `ls` is read in a
    `try`/`except` (failure → `None`). Notice the clocks: wall time
    against `ls`, and `clock` for the policy.
  - **`set_enabled(on)`:** set `_enabled`, call `mw.toolbar.draw()`, and
    notify the listeners.
